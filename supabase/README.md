# Database schema

The production database had no schema in git until now. `migrations/20261122000000_baseline.sql` is the starting point. It holds the structure of the six schemas the site and bot use (`public`, `mahjong`, `ctf`, `trpg`, `smp`, `plazmaburst`), built from the production catalog. It contains tables, constraints, indexes, sequences, types, functions, views, the trigger, RLS, policies, comments, grants and default privileges.

It does **not** contain data, sequence positions, cron jobs, or the schemas Supabase manages itself (`auth`, `storage`, `extensions`, `vault`, …).

## Files

| File | What it is |
| --- | --- |
| `migrations/20261122000000_baseline.sql` | The baseline. Loads into an empty Postgres 17 database. |
| `scripts/generate-baseline.sql` | A read-only query that rebuilds the baseline from the catalog as one text value. |
| `scripts/fingerprint.sql` | A read-only query that returns one row per object: its kind, its name and an md5 of its definition (grantors are left out). Run it on two databases and compare to prove they match. |

## Rules from here on

- Every schema change is a new file in `migrations/` named `<UTC yyyymmddhhmmss>_<what>.sql`, merged with the code that needs it.
- The baseline was **not** applied by the Supabase CLI, so production's migration history doesn't know about it. Before you link the CLI and run `supabase db push` against production, mark the baseline as applied once: `supabase migration repair --status applied 20261122000000`. Otherwise the CLI tries to create everything again. That fails on the first existing table and is rolled back, but nothing new is applied either.

## Loading it locally

The baseline grants to Supabase's roles, so create them first:

```sh
docker run -d --name fw-db -e POSTGRES_HOST_AUTH_METHOD=trust postgres:17-alpine
docker exec fw-db psql -U postgres -c "create role anon nologin; create role authenticated nologin; create role service_role nologin bypassrls; create role supabase_admin superuser nologin;"
docker cp supabase/migrations/20261122000000_baseline.sql fw-db:/baseline.sql
docker exec fw-db psql -U postgres -v ON_ERROR_STOP=1 -f /baseline.sql
```

On Git Bash, set `MSYS_NO_PATHCONV=1` so `/baseline.sql` isn't rewritten to a Windows path.

## Regenerating

1. Run `scripts/generate-baseline.sql` on production (read-only) and save the `baseline` value.
2. **Hand patch:** `plazmaburst.team_members` was renamed from `players`, and its identity sequence kept the old name. The generator doesn't emit sequence names, so change that table's `id` column to:
   `id bigint GENERATED BY DEFAULT AS IDENTITY (SEQUENCE NAME plazmaburst.players_id_seq) NOT NULL`
3. Load it locally (see above), run `scripts/fingerprint.sql` on both databases and compare. Every row must match.
